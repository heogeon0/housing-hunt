# housing-hunt

LH·SH 청년 매입임대 공고를 매일 긁어서, 신청 자격을 공고문 원문으로 판정하고,
직장까지의 출퇴근 시간 순으로 줄 세운다. 결과는 텔레그램 브리핑으로 나간다.

클라우드 routine이 매일 아침 이 스크립트를 raw URL로 받아 실행한다.

## 왜 이렇게 만들었나

원래는 조사 결과를 프롬프트에 적어두고 매일 웹서치를 시켰다. 그랬더니 적어둔 값이
썩었다. 3순위 소득 기준을 381만원으로 적어뒀지만 실제 공고문에는 1인가구 20%p 가산이
붙은 457.6만원이었고, 공고 날짜도 틀렸다. 그래서 **기준·매물·날짜를 코드에 하드코딩하지
않는다.** 전부 매일 공고문 원문에서 읽는다.

## 스크래핑 구조

두 기관 다 매물 목록이 웹페이지 본문에 없고 **첨부파일에만** 있다. 이게 핵심이다.

**LH** — 첨부가 엑셀

    목록(GET) → 상세(POST, selectWrtancInfo.do) → fileid → lhFile.do → xlsx

- 상세 엔드포인트는 `selectWrtancView.do`가 아니라 `selectWrtancInfo.do`다. 전자는 오류 페이지를 준다.
- 목록을 POST로 필터링하려면 세션 쿠키가 필요하다.
- LH 인증서에 Authority Key Identifier가 없어서 파이썬 `urllib`은 SSL 검증에 걸린다. curl은 통과한다. 그래서 HTTP는 전부 curl로 나간다.

**SH** — 첨부가 PDF, 실경로는 302에 숨어 있다

    목록(POST) → 상세(POST) → htmlConverter.do의 302 Location → PDF

- 다운로드 버튼은 JS 다운로더(Innorix)에 묶여 막힌다. 대신 "미리보기" 링크의 **302 Location 헤더가 실제 저장 경로를 흘린다.** 리다이렉트를 따라가면 안 되고 헤더만 봐야 한다.
- 날짜 경로(`2026/06`)와 해시 파일명이 공고마다 바뀌므로 하드코딩 금지.
- **User-Agent가 없으면 첨부 요청이 307로 튕긴다.**

**둘 다 목록이 게시일 역순이다.** 1페이지만 보면 접수 기간이 긴 공고를 놓친다.
실제로 이것 때문에 마감 이틀 남은 공고를 못 찾은 적이 있다.

**pypdf는 표의 셀 경계에 공백이 아니라 NUL(U+0000)을 넣는다.** `str.split()`은 NUL을
공백으로 치지 않아서, 정리하지 않으면 `100%\x00이하4,576,036`이 되어 정규식이 전부
빗나간다. 게다가 표의 숫자들이 `4,576,0366,452,897`처럼 붙어 나오므로 금액 형식으로
정확히 끊어야 한다.

## 신청 단위가 기관마다 다르다

|  | 신청 단위 | 내가 고르는 것 | 추첨되는 것 |
|---|---|---|---|
| SH | 주소지(주택형) | 건물·평형·위치 | 층·호수 |
| LH | 주택군 | 대략의 권역 | **건물·동네**·층·호수 |

LH 주택군 하나가 여러 동네의 여러 건물을 통째로 묶는다. 예를 들어 `안산상록-2`는
본오동·사동·이동에 흩어진 7개 건물 25호다. 한대앞역 도보 8분짜리에 걸릴 확률이
4%고, 절반 넘는 확률로 도보 35분 이상인 곳에 떨어진다. 그래서 **LH는 배정 확률 분포를
같이 보여주고, SH는 그냥 건물별로 줄 세운다.**

## 순위를 갈라서 판정한다

3순위가 2순위보다 유리할 수 있다. 자산 심사 대상이 다르기 때문이다.

| | 소득 심사 | 자산 심사 | 총자산 한도 |
|---|---|---|---|
| 2순위 | 본인+부모 | **본인+부모** | 3억 4,500만 |
| 3순위 | 본인만 | **본인만** | 2억 5,100만 |

2순위는 한도가 높지만 부모 자산이 통째로 합산된다. 부모가 자가를 갖고 있으면
공시가만으로 한도를 넘길 수 있다. 3순위는 본인 자산만 본다.

## 출퇴근 시간 계산

OSM 노선 관계에서 실제 역 인접 그래프를 만들고, 직장역까지 최단경로를 푼다.
상태를 (역, 타고 있는 노선)으로 두고, 노선이 바뀔 때만 환승 비용을 문다.

처음에는 "가장 가까운 4호선 역까지 직선거리로 간다"고 근사했다. 그랬더니 **없는
노선을 지어냈다.** 오리역(수인분당선)에서 인덕원(4호선)까지 13.5km를 직선으로
"타고" 용인수지를 52분으로 매겼는데, 두 역을 잇는 노선은 없고 실제로는 65~70분이다.
수원버스터미널 노드에 스냅돼서 "수원버스터미널역 도보 N분"이 나오기도 했다.
LH 주택군 30개 중 14개가 지하철이 아닌 노드에 붙어 있었다.

주의할 점 둘.
- 수인·분당선과 경의·중앙선은 `route=subway`가 아니라 `route=train`이고, 이름이
  '수인·분당선: 고색 → 왕십리'라 '수도권'으로 시작하지도 않는다. 이게 빠지면
  수원·용인 경로가 통째로 틀린다.
- 같은 환승역인데 노선마다 이름이 다르다. 4호선은 '총신대입구', 7호선은 '이수'다.
  이름만으로 이으면 환승이 끊겨서 상도동이 55분으로 나왔다(실제 30분대). 좌표가
  300m 안쪽인 역끼리도 환승으로 잇는다.

시각표 기반 정확한 경로탐색은 아니다. 실제보다 10분쯤 넉넉하게 나오는 편이다.
없는 노선을 지어내 과소평가하는 것보다는 안전한 방향이다. 필요한 건 순위지 분 단위
정답이 아니다.

## 실행

```bash
pip install pypdf

export HH_INCOME_MONTHLY=...        # 건강보험 보수월액
export HH_ASSETS_SELF=...          # 본인 총자산
export HH_MAX_COMMUTE_MIN=60

python3 hunt.py
```

개인정보는 레포에 두지 않는다. 전부 환경변수로 받는다. 값은 routine 설정에만 있다.

| 환경변수 | 설명 |
|---|---|
| `HH_INCOME_MONTHLY` | 건강보험 보수월액 (원). 실수령이 아니다. |
| `HH_ASSETS_SELF` | 본인 총자산 (원). 부동산 공시가 + 금융자산 − 부채. |
| `HH_ASSETS_PARENTS` | 본인+부모 합산 총자산 (원, 선택) |
| `HH_INCOME_PARENTS` | 본인+부모 합산 월소득 (원, 선택) |
| `HH_MAX_COMMUTE_MIN` | 이 시간을 넘으면 브리핑에서 뺀다 (기본 90) |

`stations.json`은 `build_stations.py`로 한 번 만들어 굳혀둔 것이다. 역은 안 움직이니
매일 Overpass를 때릴 이유가 없다. 노선이 연장되면 다시 돌린다.

## 깨질 수 있는 곳

- SH의 User-Agent 게이트가 조여지면 첨부를 못 받는다.
- 공고문·주택목록의 표 레이아웃이 바뀌면 정규식이 깨진다. 파싱 실패 행 수를 경고로 찍는다.
- Nominatim은 한국 주소에 약하다. 도로명 → 지번 → 동 중심 순으로 시도한다.
